# Kleinian browser acceptance

Purpose: observe actual charcoal controls around the unchanged Rust/Wasm limit-set renderer. The implementation's Rust floating-point mathematics is preserved; this job does not change numeric representations or algorithms.

Idriç-first/type-system sketch: the existing browser boundary needs Playwright pages, local HTTP servers and typed byte/string comparisons. The already qualified Ithon frontend expresses those foreign boundaries as object values with explicit bytes, text, tuple and bool admissions. This fixture follows the actual checked Ithon browser pattern rather than adding a second browser runtime to Idriç. The shell build procedure remains canonical Grease and invokes the repository's documented Cargo/wasm-bindgen architecture.

Both origins receive the same newly compiled unmodified Wasm/JS assets. The oracle requires unchanged mathematical/source bytes and exact HTML body, then executes three real symmetry types and compares every rendered canvas byte with the preceding page in phone/desktop and both system schemes. A nontrivial black/white opaque canvas is required; a blank fixture cannot pass. Controls, AA text, actual keyboard focus and a white-root negative are separate required checks. The intended scientific white canvas is an explicit exception, not a recolored application surface.

Cargo.lock, compiler versions, actual bindgen dependency and compiled Wasm hash are retained in CI evidence. Existing Cargo manifests and source remain unchanged. Current typecheck/build/browser results are pending; failures must be preserved here before repair. No unchecked Python fallback, fake renderer, network publication or Android APK claim is permitted.
